# Встроенное окружение ChatGPT и назначение ALXPRGS Workspace

**Дата ревизии:** 26.11.2026.
**Источник:** ревизия выполнена непосредственно из встроенного виртуального
окружения ChatGPT. Это **снимок одного сеанса в одной конфигурации**, а не
официальный контракт OpenAI и не гарантия доступности инструментов в другом
продукте, тарифе или сеансе.

Документ нужен, чтобы при выборе новых capability-модулей Workspace не
дублировать то, что уже доступно среде агента, и отделять уникальные
возможности от воспроизводимости и управляемости.

## 1. Как читать этот документ

Три поверхности не эквивалентны друг другу и не наследуют свойства одна другой:

| Поверхность | Что это | Как проверяется |
|---|---|---|
| Встроенное окружение ChatGPT | временная Linux-песочница сеанса | PATH, запрос версии, фактический запуск |
| Внешние коннекторы ChatGPT | доступ к внешним ресурсам через коннектор | отдельно, не эквивалентно сетевому доступу процесса |
| ALXPRGS Workspace | собственный управляемый runtime с MCP | `capabilities_list`, `server_info`, реальные задания |

Наличие программы в PATH не означает, что она функционально проверена; ниже это
явно разделено.

## 2. Ограничения встроенного окружения

- Debian 13 (Trixie), x86_64, Linux 6.18.57, glibc 2.41.
- Доступны выполнение команд, Python, временная файловая система и создание
  пользовательских артефактов; установлен Xvfb.
- Прямой HTTPS-запрос к `github.com` завершился ошибкой DNS (`curl` exit 6).
  GitHub-коннектор при этом работал. Из этого следует: сетевой доступ процесса
  нельзя предполагать, а доступ через коннектор нельзя считать эквивалентным
  доступу из процесса.
- PyTorch доступен только в CPU-варианте; CUDA недоступна.
- Окружение временное: пользовательские файлы и установленные пакеты не
  переживают сеанс и не являются общим хранилищем между задачами.

## 6. Назначение собственного Workspace

Workspace нужен не для того, чтобы повторить бинарники, которые уже есть в
среде агента, а чтобы дать то, чего у среды нет:

1. **Управляемая воспроизводимость.** Зафиксированные версии образа и
   toolchain, одинаковый результат между сеансами и машинами.
2. **Rust и тяжёлые сборки.** `rustc`, `cargo`, `clippy` отсутствуют во
   встроенном окружении; Workspace даёт их с кешами и лимитами.
3. **Изоляция и квоты.** Rootless-контейнер, отсутствие сети по умолчанию,
   жёсткие квоты по блокам и inode, лимиты CPU/RAM/PID.
4. **Жизненный цикл заданий.** Асинхронные задания, логи, exit code,
   идемпотентность, отмена, восстановление после перезапуска.
5. **Единое файловое пространство.** Файлы, правки, импорт и артефакты со
   SHA-256 и TTL-ссылками, независимые от сеанса чата.
6. **Управляемая сеть.** Egress allowlist через доверенный прокси вместо
   неявного доступа.

## 7. Обоснование будущих модулей

Новый capability-модуль оправдан, если выполнено хотя бы одно условие:

- возможность **отсутствует** во встроенном окружении (например, Rust;
  потенциально Android/Gradle — только после отдельной проверки потребности);
- возможность **есть**, но требуется воспроизводимость, управляемая версия,
  изоляция, квоты или единый жизненный цикл задания (C/C++, Python, Git,
  FFmpeg);
- возможность требует **постоянного состояния** между задачами.

Модуль не добавляется, если он лишь дублирует доступный инструмент без
требований воспроизводимости и управления. Наличие бинарника само по себе не
является обоснованием.

## 8. Маршрутизация задач

| Задача | Предпочтительная среда |
|---|---|
| Быстрые вычисления, анализ, генерация документов и медиа в одном сеансе | встроенное окружение ChatGPT |
| Доступ к разрешённым внешним ресурсам | соответствующий коннектор |
| Rust/toolchain, длительные сборки, воспроизводимые окружения, задания с квотами и артефактами | ALXPRGS Workspace через MCP |

## 9. Повторяемая ревизия

Порядок, не требующий секретов и не публикующий пользовательские данные:

1. Зафиксировать дату и продукт/сеанс, из которого выполнена ревизия.
2. Для каждой программы проверить PATH и запрос версии; отметить, что именно
   было запущено функционально.
3. Для Python — проверить импорт модуля и метаданные пакета.
4. Отдельно проверить сетевой доступ (например, HTTPS-запрос) и не переносить
   результат коннектора на процесс.
5. Не включать в отчёт переменные окружения, токены, пользовательские файлы,
   внутренние адреса и содержимое домашних каталогов.
6. Сравнить с фактическим `capabilities_list` Workspace на дату ревизии.
7. Обновить этот документ и явно отметить, что изменилось.

Снимок окружения не является постоянным контрактом: перед выбором среды
проверяйте фактический runtime, а не этот файл.
